# Redline

**A wrong number arrives wearing a convincing receipt. We catch it.**

A text-to-SQL system over construction financials joins on the wrong key, returns a number, and
explains itself in a tidy paragraph. The paragraph is generated by the same model that wrote the
query — so the receipt is written by the suspect. Nothing errors. Nothing turns red.

We don't grade the answer. **We grade the receipt against the query that actually executed** —
join keys, filters, and what got dropped — and we refuse to answer when it doesn't tie back.

## The user

A project accountant at a mid-market contractor — $50M–$500M revenue, Procore for the field, Vista
or Spectrum for the money, nobody on staff who writes integrations. Asked mid-meeting why job 1412
is over budget, her AI tool answers in three seconds. Then she opens Vista and rebuilds the number
by hand anyway.

> When she's wrong in front of the owner, it's her name on it — not the tool's.

The tool didn't save her an afternoon. It added a thing she has to check.

## Why this data

We do not fabricate the failure. **NYC publishes it.** From the dataset description NYC ships with
`fb86-vt7u`:

> Each row is uniquely identified by its Financial Management Service (FMS) ID… This ID can be
> universally joined with any OMB dataset that has the same field… FMS IDs and agency projects
> don't always have a one-to-one relationship (i.e., one project schedule may correlate to multiple
> FMS IDs, and one FMS may correct to multiple projects with different schedules).

Three claims in one paragraph and they cannot all be true. The dataset's own row label offers a
fourth answer: *"unique project and budget line combination"*.

| dataset | id | carries | key |
|---|---|---|---|
| Citywide Budget and Schedule | `fb86-vt7u` | the bridge — budget, spend, phase, schedule, agency | `fms_id` + `pid` |
| Budget Spend History and Variance | `qj5n-h5qp` | monthly snapshots; earliest = original budget, `budget_variance` = delta vs prior month | `fms_id` |
| Capital Commitment Plan | `2cmn-uidm` | committed dollars by budget line and funding source | **no `fms_id`** — keys on `budline` |

## The two failures, measured

Run it yourself:

```bash
node scripts/pull.mjs && node scripts/failures.mjs
```

Reporting period `202605`, measured 2026-08-21:

**Failure 1 — the key fans out.** 207 of 3,063 projects carry more than one FMS ID. A naive join
invents 382 surplus rows. $9,933,414,291 sits on those projects. Worst single project: pid `2845`
with 14 FMS IDs.

**Failure 2 — the join drops a third of the money and says nothing.** 2,356 rows have no project ID
at all (2,343 distinct FMS IDs among them), carrying $64,836,845,710. An inner join reports **$142,756,981,094** when
**$207,593,826,804** is actually in the period. That is **31.2%** of the portfolio, gone, with zero
errors raised.

Failure 1 double-counts *loudly* — a total that grows gets questioned. Failure 2 is the dangerous
one: it returns a smaller, tidier, entirely credible number.

`scripts/failures.mjs` asserts these figures as baselines and **exits non-zero on drift**, so the
deck and the data can't quietly disagree.

## Critical path

Each step names what it completes and what proves it finished.

| # | step | deliverable | blocked by | proof |
|---|---|---|---|---|
| 1 | Pull the data | `fb86-vt7u` + `qj5n-h5qp` local | — | 5,801 rows for period `202605` |
| 2 | Reproduce both failures | `scripts/failures.mjs` | 1 | prints 207 / 382 / $9.93B and 2,356 / $64.84B / 31.2% |
| 3 | Cardinality + anti-join guards | two assertions that throw | 2 | revert either → step 2 goes green while lying |
| 4 | Tie-out, fail closed | refusal path with tolerance | 3 | the $142.76B answer is **refused**, not served |
| 5 | Executed-query capture | SQL → AST → joins, filters, aggregates | 1 | detects the `ON p.pid = b.pid` inner join |
| 6 | Faithfulness grader | narration vs AST, scored | 5 | flags "all projects" as unsupported |
| 7 | Gold set | 30–50 cases, ≥2 seeded from step 2 | 5 | grader scores the set; 20 hand-checked |
| 8 | The one screen | answer → query → dropped rows | 4 | refusal state renders as designed, not as an error |
| 9 | Demo arc | 3 beats, rehearsed | 8 | end-to-end twice, under 3:00 |

**Only 2→3 and 5→6 are truly serial.** Everything else overlaps.

**Kill criterion:** if step 3's guards don't flip red on revert, the harness isn't real and the demo
has no second act.

## Night-before concepts

**Isha** — join cardinality (`GROUP BY key HAVING COUNT(*)>1` on both sides, always) · the anti-join
is the product (every join emits matched / unmatched-left / unmatched-right, in rows *and* dollars) ·
fail-closed tie-out (control total ± tolerance, else refuse — never degrade gracefully) · Socrata
SoQL (**`$limit` defaults to 1000** — that default alone can fake a passing demo) · the
silent-default anti-pattern from *Release It!*

**Shivam** — `sqlglot` (parse emitted SQL, walk the AST, diff joins/filters against the narration —
this makes grading deterministic instead of another LLM call) · execution accuracy vs exact-set
match, and why neither is enough · schema linking / semantic-layer retrieval · groundedness where
the evidence is an execution plan · gold sets seeded from failure modes, not easy questions · judge
calibration against ~20 hand labels.

**Devansh** — the refusal state as a designed state · receipt as progressive disclosure (number →
query → dropped rows) · `font-variant-numeric: tabular-nums` and signed deltas · semantic colour
(duplicated / dropped / reconciled) separate from the accent · failure-first demo arc.

**All three, 20 minutes together, first:** original vs revised budget · committed vs actual vs
forecast · change order · retention. If those aren't cold, every gold case skews the same direction
and the eval passes while the product lies.

## Layout

```
scripts/pull.mjs       pull NYC Open Data via Socrata. no auth, no deps.
scripts/failures.mjs   reproduce both failures; exits non-zero if the numbers drift
eval/                  gold set + graders  (Shivam)

data/                  gitignored — regenerate with pull.mjs
```

Node 18+ for built-in `fetch`. No dependencies.
